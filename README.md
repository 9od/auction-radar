# 경매레이더 · 내 집 찾기

GitHub Actions에서 법원 아파트 경매를 수집하고 GitHub Pages에서 후보와 결과를 비교합니다.

## 수집 조건

- 지역: 기존 용인 수지·성남 분당/판교 + 수원·안양·과천·하남·위례·서울 전역
- 법원: 수원 본원·성남지원·안양지원·서울중앙/동부/서부/남부/북부
- 용도: 아파트만
- 전용면적: **84~135㎡**. 공급 30~50평대의 근사 범위이며, 공급평형을 실제로 확인한 값은 아닙니다.
- 가격: **현재 회차 최저입찰가가 0원 초과~15억원 이하**. 감정가가 15억원을 초과하더라도 최저입찰가 조건을 만족하면 포함합니다.
- 신건·유찰 회차·최저입찰가율·준공연도로 추가 제외하지 않습니다.
- 가격/면적이 미확인인 물건은 조건을 만족한다고 간주하지 않습니다.

설정은 `auction_config.json`에서 관리합니다. 화면은 이번 요청의 84~135㎡/15억원 범위로 제한되어 있으므로 범위 자체를 바꾸려면 `docs/app-core.js`의 `scope`와 화면 문구도 함께 조정해야 합니다.

## 화면 사용

- **진행 중**: 기일이 지나지 않은 후보. 지역/서울 자치구/가격/주소·사건번호 검색과 정렬을 제공합니다.
- **완료·종료**: 확인된 매각·낙찰·취하·취소 등의 회차별 기록. 실제 낙찰가가 확인된 경우에만 `낙찰가 / 감정가 × 100`을 표시합니다. 취하·취소는 낙찰가율이 없습니다.
- **결과 확인 필요**: 기일이 경과했거나 변경·정지·재매각·재확인이 필요한 물건. 목록에서 사라졌다고 낙찰 처리하지 않습니다.
- 상세에서 지도/법원 원문, 회차 이력, 메모, 추천 입찰가, 제외 설정을 사용합니다.
- 기존 v1 메모·제외 항목은 법원과 사건번호가 일치하는 기록에 이전합니다. 새 기록은 법원+사건번호+물건 식별자를 사용합니다.

### ChatGPT ‘집구하기’ 프로젝트 연결

1. ChatGPT에서 집구하기 프로젝트를 열고 주소창의 URL을 복사합니다.
2. 레이더의 **설정**에 `https://chatgpt.com/g/g-p-…/project` 주소를 저장합니다.
3. 물건의 **ChatGPT 분석** → **질문 복사 + 집구하기 열기**를 누릅니다.
4. 프로젝트의 입력창에 붙여넣고 전송합니다.

법원+사건번호+주소 및 실거주 분석 요청이 준비됩니다. 특정 프로젝트로 자동 질문 전송하는 비공개 API나 지원 여부가 확인되지 않은 URL 파라미터는 사용하지 않습니다. 클립보드 권한이 없으면 요청문이 선택되어 수동 복사할 수 있습니다. 프로젝트 주소와 메모는 브라우저에만 저장됩니다.

## 영구 기록

| 파일 | 내용 |
|---|---|
| `docs/auction_data.json` | 마지막 수집 목록과 수집 상태 |
| `docs/auction_archive.json` | 조건에 해당했던 모든 물건과 회차별 관측을 누적 보관 |
| `docs/collection_status.json` | 법원별 성공·실패 내역 |

누적 JSON은 매 실행 때 기존 파일을 읽어 병합하고 Git에 커밋합니다. 목록 누락·재실행·필터 변화로 기존 기록을 삭제하지 않으며, 같은 회차/상태/금액은 중복 추가하지 않습니다. 낙찰가가 없는 매각 결과는 `null`로 남깁니다. 전용평을 공급평으로 표시하지 않습니다. 원본 데이터가 손상되면 빈 기록으로 초기화하지 않고 실패합니다.

**이 저장소는 공개 저장소입니다. 누적 경매 JSON도 공개됩니다.** 개인 메모·프로젝트 주소는 이 파일에 넣지 않습니다. 개인 메모·제외 설정은 설정 화면에서 별도 백업/복원이 가능합니다. JSON 다운로드는 백업이며 서버 업로드 기능은 아닙니다.

최초 과거 자료 복원:

```bash
python scripts/restore_history.py
```

Git에 남아 있던 목록만 복원합니다. 기존 스냅샷의 최저입찰가율을 실제 낙찰가율로 전환하지 않습니다. 이번 초기 아카이브는 104개 과거 스냅샷에서 조건에 맞는 74개 물건을 복원한 것입니다.

## 자동 수집 / 실행

Python 3.11+, Chrome과 `requirements.txt` 의존성이 필요합니다. GitHub Ubuntu 러너의 Chrome을 사용하며 Selenium이 드라이버를 관리합니다.

```bash
pip install -r requirements.txt
python scraper.py
```

- 매일 KST 오전 7시에 실행합니다. Actions → 경매 데이터 자동 수집 → Run workflow로 수동 실행할 수 있습니다.
- 기본값은 **법원별 검색 결과 앞 8페이지**입니다. 진행 목록과 최근 매각결과 목록에 각각 적용하며, 8페이지를 정상 수집하면 성공으로 처리합니다. 8페이지보다 적으면 마지막 페이지까지 수집합니다. `--pages N`으로 조정하거나 `--pages 0`으로 전체 페이지를 조회할 수 있습니다.
- 기존처럼 법원 검색 기본 순서를 따릅니다. 등록일 최신순 정렬은 확인되지 않았으므로 “가장 최근 등록된 물건”이라고 보장하지 않습니다. 보관 사건의 결과 확인은 별도 단건 조회입니다.
- 진행 목록을 수집한 뒤 최근 매각결과 목록 및 저장된 사건의 기일내역을 확인합니다.
- 법원 검색 화면의 공개 기간 밖 물건까지 무제한 과거 검색을 보장하지 않습니다. 이미 보관한 사건은 사건별 기일내역 조회 대상으로 유지합니다.
- 법원 페이지 구조 변경, 접근 차단, 모호한 복수 물건, 알 수 없는 결과코드는 추정하지 않고 수집 상태에 남깁니다. 차단을 받으면 우회/자동 재시도하지 않습니다.
- GitHub 러너에서 법원 페이지의 부가 리소스가 오래 걸릴 수 있어 브라우저 완료 신호 대신 필요한 법원 선택창만 기다리고, 일시적인 로딩 실패는 1회 재시도합니다. 실패한 Chrome 세션은 다음 법원에 재사용하지 않습니다.
- 부분실패 시 마지막 자료와 누적 기록을 보존하고 실행을 실패 상태로 표시합니다. 누락된 행을 매각으로 추정하지 않습니다.
- 현재 목록 8개 법원을 모두 수집하면 자동 실행은 성공 처리합니다. 완료결과 조회만 실패한 경우에는 사이트에 경고를 남기되 현재 목록 갱신은 성공으로 처리합니다.
- 동시 수집은 직렬화합니다. Git push 충돌 시 강제 push하지 않습니다.

### 확인된 과거 결과 수동 가져오기

공식 결과를 확인했지만 자동 조회하지 못하는 경우 아래 구조의 JSON을 준비할 수 있습니다. 법원·사건번호·주소와 기존 물건번호를 일치시키세요. 신규 기록에는 용도·전용면적·당시 최저입찰가가 필요합니다.

```json
{
  "items": [{
    "법원": "성남지원",
    "사건번호": "2025타경1234",
    "물건번호": "1",
    "소재지": "실제 원문 주소",
    "용도": "아파트",
    "전용면적": 84.5,
    "감정가": 1000000000,
    "최저입찰가": 700000000,
    "매각기일": "2026-09-01",
    "진행상황": "매각",
    "낙찰가": 920000000,
    "결과출처": "확인한 공식 원문 URL"
  }]
}
```

위 숫자는 사용법 예시이며 실제 물건/결과가 아닙니다.

```bash
python scraper.py --import-results verified-results.json
# 검토 후 docs/auction_archive.json을 커밋합니다.
```

## 검증 및 배포

```bash
python -m unittest discover -s tests -v
node tests/app-core.test.cjs
node --check docs/app.js
```

기존 GitHub Pages 설정(main 브랜치 `/docs`)을 유지합니다. 변경 브랜치를 main에 병합하면 화면이 갱신됩니다. 별도의 사이트로 이전하지 않습니다.

### 검증 범위

로컬에서는 파서 테스트, 금액·면적 경계, 법원/물건별 중복 구분, 기일 경과 분리, 실제 낙찰가율, 이력 보존, ChatGPT URL 검증을 확인했습니다. 이 작업 환경에서 법원 사이트는 WAF 응답을 반환하여 **확대 범위 실수집·매각결과 화면 구조를 종단 검증하지 못했습니다**. 첫 Actions 실행의 `collection_status.json`을 확인해야 합니다. 처음 제공되는 데이터는 확대 수집 성공 결과가 아닌 기존 기록입니다.
